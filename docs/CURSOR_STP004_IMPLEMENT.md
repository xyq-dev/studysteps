## 3. 已固定的本地开发参数

下列数值是本项目用于实现与测试的初始配置，不是法规、行业统一标准或经过真实家庭试点验证的参数。

### 3.1 登录身份、验证码与测试适配器

- `kind=PHONE`，`provider=PHONE_OTP`。provider 是稳定身份命名空间，短信厂商只影响 delivery adapter；以后更换厂商不能产生第二个账号。
- 本阶段仅支持中国大陆手机号输入：只去除 ASCII 空格和连字符，再要求匹配 `^(?:\+86)?1[3-9][0-9]{9}$`，统一查找形式为 `+86` 加 11 位本地号码；其他区号、混入字母、Unicode 数字或长度错误均拒绝。这是本阶段输入范围，不把“格式通过”当作号码真实存在或监护关系已核验。
- 验证码使用 CSPRNG 生成的 6 位数字字符串，保留前导零；有效期 5 分钟，最多 5 次失败，正确兑换单次生效。
- 同一规范化身份、用途、设备的新挑战替代此前未消费挑战，不能通过无限发码叠加有效猜测机会。发送与消费均按数据库事实判断。
- 监护关系来源固定为 `GUARDIAN_DECLARATION`。文案表述为“我声明自己是该未成年人的监护人，并确认所填信息”；不得展示为平台已核验法定关系。真实试点前仍须确认该流程及正式告知。
- 提供 `AuthDeliveryPort`。本轮实现测试 adapter，不接真实短信。仅 `APP_ENV=local|test` 且显式允许测试认证时可启用；`NODE_ENV=production` 一律拒绝该适配器，未知/缺少环境标识默认拒绝测试模式。
- 测试 adapter 只接收预置的合成测试身份，验证码只暴露给进程内测试夹具或明确的本地人工测试工具，不进入普通 API 响应、服务日志或通用调试端点。不要使用固定万能码，也不使用真实家长手机号或儿童资料。
- 人工 H5 联调可用仅回环地址、仅 local 环境、独立随机访问密钥保护的本地测试工具读取测试收件箱；它不能作为应用公共路由或被生产构建启用。优先直接通过测试夹具驱动浏览器完成认证，避免额外维护工具。

### 3.2 限频与失败次数

| 动作/维度 | 初始限制 |
| --- | --- |
| 发验证码，规范化身份聚合 SIGN_IN 与 STEP_UP | 间隔至少 60 秒，5 次/小时，10 次/天 |
| 发验证码，设备 | 10 次/小时，30 次/天 |
| 发验证码，来源 IP | 20 次/小时，100 次/天 |
| 登录/二次验证失败，规范化身份 | 10 次/15 分钟，达到后该窗口内拒绝继续尝试 |
| 登录/二次验证/配对兑换，设备聚合 | 20 次/分钟 |
| 登录/二次验证/配对兑换，IP 聚合 | 60 次/分钟 |
| 新建配对，指定学生档案 | 间隔至少 30 秒，5 次/小时 |
| 指定 challenge 或 pairing 的错误码 | 最多 5 次失败，达到后锁定该凭证 |

除单独标明的间隔冷却外，计数窗口按服务端 UTC 对齐的固定窗口实现。各维度同时约束；客户端设备 ID 可伪造，只作为辅助，不能替代身份、IP 与凭证行计数。IP 从真实连接/明确受信代理取得，不信任任意转发头。拒绝返回 429 与安全的重试提示，不泄露账号是否存在。

限频计数需在多进程下有效，可使用 PostgreSQL 原子计数表/事务，不新增 Redis 基础设施。必要的新计数表允许纳入本次 Schema 与 migration，并登记约束和用途；应用重启不能清空有效窗口。窗口内重复请求不能绕过 challenge 的单次消费与最大失败次数。

## 4. 实现前必须统一的具体规则

### 4.1 撤回同意的版本参数冲突

原设计第 9.1 节把同意撤回定义为不要求 version 的单调撤销，而第 9.2 节端点表要求 expectedStudentVersion。统一为：撤回请求使用目标 consentId、原因码及 Idempotency-Key，不要求 expectedStudentVersion；在事务锁内重验当前主体、关系和目标记录。明确拒绝未定义的权威字段，客户端不能决定撤回人和时间。并发可替换操作、普通资料修改和新同意授予继续遵循原有 expectedVersion 规则。

同步修正设计、contracts、API 表、客户端和测试，不能在两套规则之间任选一种。

### 4.2 重放旧撤回不能撤销后来的新授权

同意撤回只影响路径指向的记录。对已撤回或已替代记录的重复操作不重复施加限制，也不撤销后续新授权生成的会话。仍须鉴权，不能返回跨档案的历史结果。

成功撤回当前有效记录后，在同一事务重算全部当前必需政策：只有确实缺失必要同意时，才限制档案并撤销学生会话/配对。重放只能恢复既有操作结果，不重新执行副作用；响应同时提供安全的当前访问状态或要求客户端重新读取，不能拿旧操作的受限快照覆盖现状。

新增真实数据库测试：撤回 C1 → 明确接受当前版本生成 C2 → 取得新会话 → 重复撤回 C1；C2 与新会话保持有效，C1 的旧会话仍不可复活。并发执行同样可线性化。保留 T11 原有撤回核心测试。

### 4.3 失败次数必须真正落库

错误验证码/配对码需原子累加并提交失败计数，再返回认证失败。不能在同一个事务里增加计数后直接抛出导致事务整体回滚的 HTTP 异常，让次数永远不增长。数据库异常/业务不完整时仍需回滚；区分认证拒绝结果与数据库故障。

新增测试：连续错误、跨进程错误、并发错误、最后一次允许尝试与正确兑换竞争。失败尝试到达上限后正确码也不能继续兑换，超时也不能恢复已锁定凭证。

执行任何迁移前，记录测试实例的创建来源、进程/容器或测试服务身份、数据库与角色的隔离证据，凭证脱敏。仅数据库名字含 test、或地址是 localhost，均不足以证明隔离；不能误连本地代理后的生产库。只允许使用明确为本任务创建、无用户数据的测试库。不执行 migrate reset，不清理不属于本任务的对象。

如果本机确实没有可用测试 PostgreSQL，继续完成代码、migration 文件、自动化测试和隔离测试/CI 配置，并运行不依赖数据库的有效检查；将 B07 记录为尚未执行的验收条件，列出具体缺少的运行条件。不要用 SQLite、PGlite、内存 repository 或 mock 宣称真实 PostgreSQL 验收通过，也不要伪造 CI 结果。

必须验收：

- 实际根命令的类型检查和构建、Prisma Schema 验证与 Client 生成；命令以仓库定义为准，修复本次引入的问题。
- 原设计第 11 节本阶段应执行的用例，尤其 T01、T02-B、T10、T11 核心子项、AUTH、PAIR、CON、IDEM、DB、TX、TIME。
- 本文件新增的撤回版本一致性、旧撤回重放、失败计数提交，以及配置关闭测试模式、限频、idle/absolute 超时边界。
- 多条数据库连接开启真实重叠事务，覆盖身份首次创建、配对创建/兑换/撤销、授权写入/撤销竞争。用同步屏障保证事务实际竞争，不只用顺序测试或无竞争的 Promise.all 代替。

## 8. 设计参考

会话在服务端到期并执行撤销、配置独立闲置与绝对期限的原则参考 [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。本文件的具体期限由本项目选择。

限制认证尝试、同时考虑主体与来源维度的原则参考 [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。本文件的限额不是 OWASP 指定值。

CSRF 必须与当前会话绑定、不能只比较两个客户端值，来源检查作为配合措施，参考 [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。继续采用已有设计的服务端 session 摘要校验，不改成无会话绑定的双提交。
