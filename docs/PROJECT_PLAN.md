# 学生自主学习应用项目方案

*产品规划与开发交接方案*

版本 V1.0　编制日期 2026年9月13日　项目代号 StudySteps

面向英群及后续设计、开发、测试人员。本方案覆盖产品定位、学段年级、学生与家长协作、页面流程、任务规则、数据与接口、交付计划和验收标准。StudySteps 仅作为工程代号，正式名称与品牌另行确定。

建议建立一个独立的学生自主学习产品。先用手机网页完成“自己安排任务、开始学习、记录成果、每周调整”的核心流程，再依据试点反馈扩展微信小程序和原生应用。首期完整支持小学、初中、高中年级选择，重点验证小学三至六年级家庭的使用体验。大学及成人学习预留分类，第二阶段再完善专用模板。

首期成功标准是孩子能更少依赖催促地完成自己参与制定的计划。产品以任务完成、计划调整和个人进步为主要反馈，学习时长只作为辅助记录。成绩提升不作为未经验证的宣传承诺。

| **决策项** | **本方案采用的默认方案** |
| --- | --- |
| 使用场景 | 家庭课后学习，兼容孩子独立设备与家长共用设备 |
| 首发形态 | 手机优先的 H5，兼容平板；后台使用桌面网页 |
| 首发用户 | 支持小学至高中；试点优先小学三至六年级 |
| 核心导航 | 打卡、计划、成长、我的 |
| 家长参与 | 协助开通、建议计划、查看授权范围内的总结 |
| 技术路线 | TypeScript 前后端、模块化单体、独立数据库 |
| 开发节奏 | 42至58人日工程估算，另安排14天家庭试用 |
| 商业化节奏 | 先验证持续使用，再研究家长付费的家庭增值功能 |

本方案中的任务时长、模板数量、试点指标和排期均为可调整的产品或工程设定。它们不代表统一教育标准、市场统计或供应商报价。

## 1 产品定位与范围

### 1.1 要解决的问题

孩子常见的困难是目标过大、下一步不明确、计划与当天精力不匹配，以及记录后看不到具体进步。家长则需要知道孩子是否有困难、哪里可以协助，同时避免每天重复布置和催促。首期围绕这些情境组织功能。

产品提供三个直接价值：把“我要好好学习”拆成今天可完成的事项；让学习过程有开始、结束和调整的入口；让孩子与家长以具体记录讨论下周安排。模板帮助起步，孩子始终可以修改任务内容和顺序。

### 1.2 首期边界

首期提供学习计划、习惯记录、可选计时、简单复盘及家庭协作。账号、权限、数据导出与删除属于完整产品的一部分，应与核心业务同时交付。

题库、拍照搜题、自动批改、AI聊天老师、公开学习社区、陌生人私信、班级管理、直播课程、实物奖励商城及在线支付暂不进入首期。后续只有在明确用户问题和新增成本后才分别立项。

### 1.3 与现有项目的关系

本项目独立于 Yuwang／渔网杯。使用独立仓库、数据库、运行环境、账号域和素材空间。可以沿用已有的文档规范、代码审查方式和通用工程经验；不共用Yuwang账号、订单、支付数据或业务权限。

## 2 学段年级与个性化系统

### 2.1 分类结构

数据采用“学段、学制、年级、学期、科目、个人目标”的组合。学段用于组织模板；年级用于筛选默认内容；学期用于归档和切换；个人目标用于决定真正展示哪些任务。

| **学段分组** | **年级范围** | **默认计划方式** | **家长与界面重点** |
| --- | --- | --- | --- |
| 小学低年级 | 一至二年级 | 一次一个小任务，图形提示，允许家长代录 | 大按钮、少文字、陪伴操作 |
| 小学中年级 | 三至四年级 | 每日重点，作业与阅读分开，练习自主排序 | 孩子选择，家长提供建议 |
| 小学高年级 | 五至六年级 | 周目标拆成日任务，增加预习和复习 | 简化插画，逐渐独立制定 |
| 初中 | 六三制初一至初三；五四制含初四 | 按科目安排一周，错题复习与考试准备 | 信息紧凑，展示任务负担 |
| 高中 | 高一、高二、高三 | 阶段目标、学科专题、周期复习 | 自主调整，弱化卡通和奖励 |
| 大学及其他 | 自定义阶段或学期 | 课程、考证、项目与长期目标 | 第二阶段提供独立模板 |

默认采用常见的六三学制，同时支持五四学制和自定义年级。不要将年级简单存成全局数字并假定所有用户的小学都是六年。推荐字段为 stage_code、school_system、grade_code、grade_label、term_code。

### 2.2 科目模板

小学模板提供语文、数学、英语、阅读、运动与自定义分类；初中、高中增加可选学科列表。科目由学生或家长选择，不自动把所有学科加入计划。科目出现的具体年级、课程版本和选科组合允许配置，不把模板当作全国统一课表。

首期配置12个常见年级入口。建议每个年级提供3个原创模板，共36个，分别覆盖日常安排、阅读或复习习惯、周计划。每个模板最多包含少量示例任务，导入前必须预览并可取消。

### 2.3 年级与年龄分离

年级不能作为判断年龄或监护权限的依据。另设年龄段记录和确认来源，例如未满14岁、14至17岁、18岁及以上、尚未确认，并保留确认日期。年龄尚未确认时先展示静态体验页，不创建正式学习记录。

首期建议所有未满18岁档案由监护人开通，这是便于试点管理的产品选择。其中处理未满14岁儿童个人信息须落实监护人同意及专门规则，见第13章。成年用户独立开通的完整流程安排在第二阶段。[[S5]](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

### 2.4 升级年级与个体差异

新学年只提示确认，不静默修改年级、科目和现有计划。升年级后保留过去记录的年级快照；新模板由用户选择导入。留级、跳级、休学和跨学制通过明确的档案调整流程处理。

同一年级允许选择较轻、标准、自定义三类任务规模。产品不推断孩子的智力或学习能力，不生成“自律差”等标签。默认时长只用于计划预估，用户可以关闭时长展示。

## 3 用户角色与首次使用

### 3.1 角色权限

权限以具体学生档案及其有效授权关系为边界，不能仅凭一个 family_id 访问全部孩子。管理员使用独立账号体系。

| **角色** | **允许操作** | **主要边界** |
| --- | --- | --- |
| 学生 | 查看自己的任务、安排顺序、记录完成、调整计划、复盘 | 不能查看其他学生，不能进入家长管理 |
| 主监护人 | 开通档案、授权设备、建议计划、查看约定范围内的记录 | 不静默冒用学生身份完成任务 |
| 协作监护人 | 第二阶段按邀请获得指定档案的部分权限 | 非家庭成员默认无权访问 |
| 内容管理员 | 配置年级科目、编辑及发布模板 | 默认不能浏览学生照片或复盘正文 |
| 支持人员 | 处理账号与数据请求，按工单获得必要权限 | 临时授权、可追溯，禁止全库随意查询 |

首期支持一个主监护人管理多个学生档案。复杂家庭共同监护、争议解绑和主监护人转移通过人工核实处理；不提供自动夺取档案权限的入口。

### 3.2 开通流程

监护人验证账号后，阅读适用的告知与授权内容，选择孩子的年龄段、学段、学制和年级，设置昵称与内置头像。随后与孩子共同选择关注的科目、通常可用的时间段和一个计划模板，预览并修改后保存。

不将真实姓名、学校、班级、定位、通讯录或人脸识别作为普通打卡的必要字段。学生端可以在家长设备切换档案，也可以通过监护人生成的短期单次配对码绑定独立设备。

### 3.3 共用设备与独立设备

进入学生模式后，服务端签发仅能访问该学生档案的会话。切回家长模式需要二次验证，不能只依赖前端隐藏按钮。配对码建议10分钟失效、使用一次作废、存储摘要并限制尝试次数。

设备丢失时，监护人可以撤销该设备会话。撤销后停止同步并清理本地敏感缓存；未同步的内容明确提示其处理结果，不能继续静默提交。

## 4 核心使用流程

### 4.1 每日流程

打开首页后，先看到当前学生、今天的任务和最适合开始的一项。孩子可以调整顺序或缩小任务，再选择直接学习或使用计时。学习结束后记录完成结果，也可以选择部分完成、遇到困难或稍后继续。

完成一项任务会自动形成当日学习记录。首页不再设置一个与任务无关的大型“签到领积分”按钮。任务记录区分学生自报、家长代录和后补记录，界面不把自报结果宣称为已经验证的学习效果。

### 4.2 每周流程

周末展示本周完成了什么、哪些任务多次调整、哪些地方需要帮助。孩子用三个简短问题完成复盘：本周做得顺利的事是什么，遇到了什么困难，下周准备改哪一件事。允许跳过长文字，用选项与一句话回答。

系统根据记录提供可解释的调整建议，例如“这项任务本周推迟了3次，可以拆小或换时间”。用户确认后才修改下周计划。首期用确定性的规则生成建议，不依赖大模型。

### 4.3 家长协作流程

家长从家庭总览进入某个孩子的周总结，看到完成事项和求助请求，再给出一条具体反馈。家长新增计划时默认作为建议，由孩子在计划页确认；低年级可选择共同制定模式，由家长记录双方约定。

学生复盘正文默认个人可见，孩子可以主动分享给监护人。家长需要看到的求助内容通过明确的“请家长帮忙”动作分享。基础学习统计的可见范围在开通时清楚说明。

## 5 功能范围与优先级

P0表示完成试点所需；P1表示试点通过后的扩展；P2表示另行评估的功能。优先级不代表开发完成状态。

| **模块** | **P0 必须交付** | **P1 或 P2 扩展** |
| --- | --- | --- |
| 档案与授权 | 年龄段、学制年级、多档案、设备配对、撤销 | 协作监护人、自主账号接管 |
| 计划 | 单次、每日、指定星期、起止日期、暂停、调整 | 每周完成若干次、复杂周期规则 |
| 今日任务 | 排序、重点任务、完成标准、困难与延期 | 自动负担建议、更丰富分组 |
| 完成记录 | 手动确认、数量结果、可选心得、代录标记 | 可选照片、语音转文字 |
| 学习计时 | 开始、暂停、结束、异常会话恢复 | 原生后台能力与系统提醒 |
| 成长 | 月历、本周统计、简短复盘、3种徽章 | 更多主题、学期报告、导出样式 |
| 家长 | 周总结、计划建议、求助回应、设备管理 | 多监护协作和家庭自定义约定 |
| 后台 | 分类、模板发布、账号支持、数据请求、审计 | 模板实验、内容版本比较 |
| 通知 | 站内消息、用户打开后的到期提示 | 经用户授权的渠道提醒 |
| 数据服务 | 导出、删除申请、备份恢复、必要监控 | 更完整的迁移与跨设备能力 |

照片功能放在P1，可以减少首期上传、审核、删除链路和儿童影像处理的成本。P0的完成标准用文字、数字与勾选表达，足以验证是否有人持续使用。

## 6 学生端页面设计

### 6.1 页面清单

以下编号用于设计稿、任务单、接口联调和验收报告追踪。筛选弹层、日期选择器和通用确认框作为组件，不重复计作独立业务页。

| **编号** | **页面** | **必须呈现的信息与操作** |
| --- | --- | --- |
| S01 | 身份与适龄引导 | 学生或家长入口、年龄确认、授权说明 |
| S02 | 学习档案设置 | 学制、年级、学期、昵称、科目 |
| S03 | 初次计划预览 | 模板任务、预计负担、删改与确认 |
| S04 | 打卡首页 | 当前档案、今日重点、待完成与已完成任务 |
| S05 | 学习计划总览 | 周日历、日任务、科目筛选、新建入口 |
| S06 | 新建计划 | 目标、科目、任务标准、重复方式、起止日期 |
| S07 | 计划模板库 | 当前年级筛选、任务示例、预计安排、预览导入 |
| S08 | 计划详情 | 目标、任务列表、执行记录、编辑与暂停 |
| S09 | 任务详情 | 完成标准、步骤、历史调整、开始与直接记录 |
| S10 | 专注学习 | 当前任务、计时、暂停、结束与异常恢复 |
| S11 | 完成记录 | 实际完成内容、数量、可选心得、遇到困难 |
| S12 | 任务调整 | 本次或未来任务、日期、拆分、调整原因 |
| S13 | 成长总览 | 本周记录、月历、个人趋势与徽章入口 |
| S14 | 学习日历 | 每日状态、任务明细、休息与补记标识 |
| S15 | 每周复盘 | 三个简短问题、下周一项调整 |
| S16 | 徽章记录 | 获得条件、获得日期、历史成果 |
| S17 | 我的 | 档案、年级调整、消息、设备、设置 |
| S18 | 设置与数据 | 提醒、隐私范围、导出、删除与反馈 |

### 6.2 学习计划总览

顶部显示“本周计划”和切换周的控件，下方为七日横向日历。默认选择今天，日期下用小点或数字表达任务量，不用纯颜色区分状态。正文展示所选日期任务，提供全部、待完成、已完成筛选，以及科目筛选。

每条任务显示科目、名称、明确完成标准、预计时长和状态。任务多时按学习时段或科目折叠。新建入口持续可见；空状态提供“自己添加”和“选择模板”两种起步方式。

### 6.3 新建计划与编辑

创建分三步：先写目标和科目，再定义任务及完成标准，最后安排日期与重复方式。保存前显示未来一周预览与估计任务量。初次仅必填名称、完成标准和日期；提醒、步骤与备注折叠为可选项。

编辑必须明确影响范围：“仅这一次”或“从选定日期起的未来任务”。已完成记录和历史完成标准不被覆盖。删除长期计划采用归档；未完成的未来安排可以取消，过去的记录继续可查。

### 6.4 任务执行与完成

开始学习提供“使用计时”和“直接去学习”两条等价入口。计时结束不会自动完成任务。提交记录时显示事先约定的标准，例如“阅读10页”；未达到标准可记录部分进度或拆成后续任务。

完成页先反馈具体成果，例如“今天完成了10页阅读”，再提供“下一项”与“结束今天”。庆祝动效短暂、可关闭，不要求分享、看广告或领取奖品才算完成。

### 6.5 空状态与异常状态

至少设计首次无计划、今天休息、全部完成、任务逾期、加载中、请求失败、离线未同步、登录失效、无权限、计划已暂停十种状态。离线提交显示“待同步”，收到服务端确认后再显示完成与奖励，失败可重试且不丢失输入。

## 7 家长端与管理后台

### 7.1 家长端页面

家长与学生共享账号基础设施，使用不同的业务入口和授权范围。手机端家长导航采用“家庭、建议、我的”，避免将儿童打卡导航原样套用。

| **编号** | **页面** | **主要内容** |
| --- | --- | --- |
| P01 | 家庭总览 | 孩子档案切换、本周摘要、待回应求助 |
| P02 | 孩子学习总结 | 任务成果、调整情况、可见的复盘内容 |
| P03 | 计划建议 | 新增或调整建议、孩子反馈、共同确认记录 |
| P04 | 鼓励与回应 | 基于具体成果的反馈、求助处理 |
| P05 | 档案与设备 | 年龄段确认、年级调整、配对和撤销 |
| P06 | 授权与数据 | 同意记录、可见范围、导出、删除申请 |

家长代录需要显式选择“代孩子记录”，保存实际操作人。提醒以汇总为主；同一项困难不连续轰炸家长。反馈文案围绕努力、方法与下一步，不展示同学排名。

### 7.2 管理后台页面

| **编号** | **页面** | **功能与边界** |
| --- | --- | --- |
| A01 | 运行概况 | 匿名汇总、同步失败、错误趋势 |
| A02 | 学段科目配置 | 学制、年级、科目及其关联 |
| A03 | 模板管理 | 编辑、审核、预览、发布、下架与版本 |
| A04 | 账号支持 | 按工单定位档案、设备撤销、必要信息遮罩 |
| A05 | 数据请求 | 导出与删除工单、执行进度、结果记录 |
| A06 | 审计与设置 | 敏感操作记录、角色权限、通知参数 |

后台优先解决内容维护和服务支持，首期不建设复杂经营大屏。模板下架只阻止后续导入，不自动删除学生已经创建的计划。

## 9 任务模板与业务规则

### 9.1 模板内容示例

以下内容展示任务如何表达，不规定孩子必须学习的数量或时间。所有数量、时长和周期均由使用者确认，避免把成人设定的模板直接变成强制要求。

| **对象** | **模板任务** | **完成标准示例** | **复盘提示** |
| --- | --- | --- | --- |
| 小学二年级 | 亲子阅读 | 读完一篇自己选的短文 | 最喜欢哪一段 |
| 小学四年级 | 数学巩固 | 完成自己选的5道题，标出不会的题 | 哪一步需要帮助 |
| 小学六年级 | 英语复习 | 复习10个单词并自测一次 | 下次重点复习什么 |
| 初二 | 错题回顾 | 重做2道错题并记录出错原因 | 方法有何变化 |
| 高二 | 学科专题 | 完成一个知识点梳理和一组练习 | 还存在什么疑问 |

任务字段包括名称、科目、完成标准、可选数量与单位、预计时长、开始日期、截止日期、重复规则、可选步骤、提醒、来源和制定方式。来源区分自主创建、模板导入、家长建议与家长代建。

### 9.2 任务安排与变更

P0支持单次、每天、每周指定日期三类重复规则，均设置起止日期或明确的持续标记。暂不实现任意自然语言重复规则。任务分为长期规则和某一天的实例：修改长期规则不能改写已完成实例。

改期时保留同一个实例ID和最初安排日期，更新当前安排日期并写入调整记录。一个任务改到已有同类任务的日期时提示有两项安排，允许保留或由用户明确取消其中一项，不能自动覆盖。

暂停计划取消尚未开始的未来安排，恢复后只继续未来任务，不自动补出暂停期间的所有任务。归档计划保留历史。任务拆分为多个后续实例时记录来源关系，原任务取消并注明拆分，不能同时再算一次完成。

### 9.3 状态与完成口径

| **对象** | **状态** | **关键规则** |
| --- | --- | --- |
| 长期计划 | 草稿、启用、暂停、归档 | 暂停和归档均不破坏历史记录 |
| 任务实例 | 待开始、进行中、已完成、已跳过、已取消 | 逾期由日期推导，允许后续补记 |
| 学习会话 | 计时中、暂停、待确认、已结束、已放弃 | 一名学生最多一个未结束会话 |
| 计划建议 | 待回应、已接受、已拒绝、已撤回 | 已接受后生成明确的计划变更 |
| 同步操作 | 待同步、成功、失败、冲突 | 失败允许重试，不能重复生成记录 |

“部分完成”记录当前进度，任务保持进行中；确认达到标准后才标记完成，家长代录需标明来源。完成记录与家长反馈独立，首期不要求家长逐条审核才生效。家长可以提出修正建议，修正后保留操作轨迹。

一次完成动作包含任务状态变更、完成记录、当日汇总和徽章事件，必须在同一事务边界内形成一致结果。重复点击、网络重试和离线重放只能产生一次有效完成。

### 9.4 补记与撤销

建议允许补记最近7个自然日。用户选择实际学习日期，系统同时保留服务端接收时间、操作人及补记标识。不得将服务端接收时间伪装成过去，也不把补记当作按时完成。

撤销完成回到待开始或进行中，并撤销对应的有效完成事件。任何奖励都按原业务事件去重，重复完成不能再次刷取。补记和修正更新报告时增加报告版本与修正说明。

### 9.5 计时与跨天

客户端倒计时只负责显示，服务端保存会话开始、暂停、恢复与结束时间。以时间戳计算累计时长，不能依赖页面每秒执行的回调。浏览器后台计时会受到节流，网页不承诺系统级锁屏管理或强制专注。[[S8]](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)

建议异常会话在连续90分钟未交互后转为待确认，此值是可调整的产品保护参数。再次打开时询问实际学习情况，未经确认的长时间段不自动进入统计。用户可选择“没有学习”或修正时长。

跨午夜会话按学生时区拆分时长，任务仍按指定学习日期归档。设备时间异常、长时间离线或会话重叠需要提示确认，服务端拒绝负数与明显不合理时长。计时长度不决定完成或奖励数量。

### 9.6 打卡与成长反馈

当日存在至少一条有效完成记录，就显示当日已学习；该标记由记录推导，不单独存一个可任意累加的签到次数。计划休息日独立展示，未完成也不清空过去的累计成果。

首页主要展示本周学习天数和完成事项。若提供连续记录，必须同时解释休息日与补记口径；首期不将连续天数做成主要奖励条件。

首期仅设置首次完成、累计5个学习日、完成首次周复盘三种非消耗型徽章。条件与事件固定、无随机抽奖、不与付费相关。任务撤销导致条件不满足时重新计算当前资格，并保留必要事件审计。

## 10 数据模型与一致性

### 10.1 核心实体

采用关系数据库，先建立清楚的业务约束。下表列出逻辑实体，实施时可合并简单配置表，但不得把计划规则和每日任务实例混为同一条可反复覆盖的记录。

| **实体** | **核心字段或关系** | **约束重点** |
| --- | --- | --- |
| Account | 主监护人身份、登录方式、状态 | 不把学生档案ID当登录凭证 |
| StudentProfile | 年龄段、学制、年级、学期、时区 | 所有学习数据归属一个档案 |
| GuardianLink | 账号、学生、权限范围、状态 | 每次访问检查有效关系 |
| ConsentRecord | 规则版本、范围、同意时间、主体 | 撤回与历史记录可追溯 |
| DeviceSession | 会话范围、设备、过期、撤销 | 学生会话不能提升为家长权限 |
| Subject与GradeConfig | 科目与学段年级映射 | 支持自定义及配置版本 |
| PlanTemplateVersion | 模板内容、适用范围、发布状态 | 导入后保存内容快照 |
| StudyPlan | 学生、目标、周期、状态、制定方式 | 与历史实例分离 |
| TaskSeries | 计划、完成标准、重复规则、版本 | 规则变更有生效日期 |
| TaskOccurrence | 稳定ID、原始日期、当前日期、状态、快照 | 同一规则与发生键唯一 |
| CompletionRecord | 实例、操作人、学习日期、接收时间、有效性 | 每个实例仅一条有效完成 |
| StudySession | 学生、任务、时间区间、状态 | 同一学生仅一个活动会话 |
| Reflection与WeeklyReport | 学生、周起点、可见范围、报告版本 | 正文与汇总分开授权 |
| PlanSuggestion | 监护人、学生、变更内容、回应状态 | 接受动作幂等 |
| BadgeEvent与OutboxEvent | 条件事件、去重键、处理状态 | 可重试且不重复生效 |
| AuditLog与DataRequest | 操作摘要、请求状态、处理记录 | 不记录敏感正文和访问令牌 |

首期不接照片，但为后续Attachment保留关联位置。上传功能上线前再增加对象归属、状态、大小类型、删除期限和访问策略，不先建公开素材目录存学生内容。

### 10.2 唯一键与事务

TaskOccurrence使用唯一键“series_id＋occurrence_key”，其中occurrence_key来自该规则最初安排的本地日期，改期不变。P0一条重复规则每天最多一个实例；同一天需要两次练习时建立两条规则。

对有效完成记录设置每实例唯一约束，对活动会话设置每学生唯一约束，对徽章事件和Outbox事件设置业务去重键。接口使用Idempotency-Key，并将键绑定到操作主体、接口与请求内容摘要；同键不同内容返回冲突。

写入携带version用于乐观锁。家长与学生同时修改同一计划时返回409并展示差异，用户合并确认后重试。不能默认使用最后一次写入覆盖所有字段。

### 10.3 时间与历史

时间戳统一存UTC，学习日另存本地日期与当时的时区快照，默认Asia/Shanghai。历史任务保存年级、科目名称、完成标准和规则版本，后续改年级或改模板不重新解释过去。

定时任务预生成未来14天实例，读取日程时补齐缺失范围，两种入口共享唯一约束。任务生成、报告生成及提醒通过事务Outbox推进，失败允许重试。后台任务不得凭队列消息内的旧权限直接发送敏感内容。

### 10.4 统计口径

首页“已完成／计划任务”按当前选定日期的有效安排计算，排除已取消任务；跳过计入未完成。计划调整数量单独展示。当天无有效任务时展示休息或尚无计划，不显示0%制造失败感。

周报保留首次生成时的安排数、调整数、完成数和按时完成数。后补记录更新版本，补记计入实际学习日但不计入按时完成。任何比例都同时提供分子、分母及时间范围，不能混用当前计划与旧报告快照。

## 11 接口与模块边界

### 11.1 API 约定

统一使用HTTPS与JSON，业务路径以/v1开始。列表采用游标或稳定排序分页；时间采用ISO格式；业务错误返回code、message、requestId及必要字段。对未授权的学生对象统一返回不会泄露其存在性的错误响应。

| **接口组** | **代表接口** | **用途** |
| --- | --- | --- |
| 身份 | POST /v1/auth/code；POST /v1/auth/session | 验证账号并建立受限会话 |
| 档案 | GET／POST /v1/students | 列出授权档案或创建档案 |
| 配对 | POST /v1/students/:id/pairings | 生成单次配对码 |
| 授权 | POST /v1/students/:id/consents | 记录或更新适用同意 |
| 模板 | GET /v1/templates | 根据年级科目筛选模板 |
| 计划 | GET／POST /v1/students/:id/plans | 查询与新建计划 |
| 规则 | PATCH /v1/plans/:id/series/:seriesId | 指定范围调整未来规则 |
| 日程 | GET /v1/students/:id/tasks?date=YYYY-MM-DD | 读取指定学习日 |
| 完成 | POST /v1/tasks/:id/completions | 幂等提交自报或代录完成 |
| 撤销 | POST /v1/completions/:id/revoke | 撤销有效完成并同步统计 |
| 调整 | POST /v1/tasks/:id/reschedule | 改期并记录原因和原始安排 |
| 计时 | POST /v1/students/:id/sessions；POST /v1/sessions/:id/actions | 创建及暂停恢复结束会话 |
| 复盘 | PUT /v1/students/:id/reflections/:week | 保存复盘及可见范围 |
| 报告 | GET /v1/students/:id/reports/weekly | 返回版本化周报告 |
| 建议 | POST /v1/students/:id/suggestions；POST /v1/suggestions/:id/respond | 提议并确认计划调整 |
| 数据请求 | POST /v1/students/:id/data-requests | 发起导出或删除 |

### 11.2 完成接口约束

提交内容包含taskVersion、completedForDate、实际完成数量、可选心得和来源类型。操作人从认证会话读取，客户端不能任意传另一个accountId代替自己。

服务端依次验证会话与授权、任务归属和状态、补记窗口、参数与版本，再写入完成、汇总和事件。响应至少包含completionId、taskStatus、daySummary、reportVersion、serverTime。重复的同内容请求返回已成功结果。

### 11.3 提醒与后台任务

P0只承诺站内消息和打开页面后的到期提示。默认安静时段建议21:00至次日07:00，用户可调整；这是提醒参数，不作为睡眠指导。多项任务尽量合并为一条摘要。

P1接入具体通知渠道前验证平台授权、触达范围和撤销机制。消息发送前再次检查档案状态、关系、同意范围和偏好。第三方故障不会阻塞任务完成或报告查看。

## 12 技术架构与开源参考

### 12.1 首发形态选择

| **形态** | **适合场景** | **主要工作与限制** | **本方案定位** |
| --- | --- | --- | --- |
| 手机H5 | 快速邀请家庭试用，共用设备与平板 | 浏览器后台、通知和安装能力不统一 | 首期实现 |
| 微信小程序 | 家长微信入口、分享和轻量使用 | 独立前端适配、审核及平台能力核验 | 试点后决定 |
| 原生或Flutter App | 长期独立使用、更完整设备能力 | 分发上架、系统差异、维护成本 | 核心需求稳定后 |

手机H5优先是当前预算和验证效率下的工程建议。若首批家庭明确只能使用微信入口，可将小程序前置，但保持数据模型和服务接口，重新估算前端适配与发布工作。

### 12.2 推荐组件

| **层次** | **建议选型** | **原因与实施边界** |
| --- | --- | --- |
| 学生与家长前端 | React、TypeScript、Vite | 手机优先，共用组件与明确的类型契约 |
| 管理后台 | React、TypeScript | 复用语言与鉴权客户端，独立权限入口 |
| API | NestJS、TypeScript | 按业务模块组织认证、计划、报告等逻辑 |
| 数据 | PostgreSQL、Prisma | 关系约束、事务、版本化迁移 |
| 后台任务 | 单体进程的工作任务与数据库Outbox | 首期减少组件，达到负载需求再引入专门队列 |
| 文件 | P1使用独立的私有OSS或兼容对象存储 | 与公共UI素材隔离，短时授权访问 |
| 部署 | Docker、独立测试和生产环境、HTTPS反向代理 | 可回滚、可备份、环境清晰 |
| 监控 | 错误追踪、结构化日志、健康检查 | 敏感字段脱敏，日志保留期可配置 |

NestJS用于服务端模块组织，Vite用于前端构建。具体版本在项目初始化时选择相互兼容的稳定版本并锁定依赖；不在本方案中承诺未经实际安装验证的版本组合。[[S9]](https://docs.nestjs.com/)[[S10]](https://vite.dev/guide/)

业务模块建议为identity、profiles、consents、catalog、planning、tracking、reflection、reports、family、notifications、admin。它们部署为一个API应用，先保持模块边界；首期无需微服务、独立搜索集群或向量数据库。

## 13 未成年人数据与安全设计

### 13.1 授权与最小化收集

按面向中国大陆家庭的产品进行设计。《个人信息保护法》将不满14岁未成年人的个人信息列为敏感个人信息，并规定相应监护人同意及专门处理规则。开通流程需要独立呈现适用的告知、必要性与授权内容，保留规则版本及同意记录。[[S5]](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

《儿童个人信息网络保护规定》涉及专门规则、明确告知、最小授权、删除和第三方处理等要求。上线前应指定实际负责人员，核定授权方式与数据处理清单；一个勾选框不能代替完整流程。[[S6]](https://www.cac.gov.cn/2019-08/23/c_1124913903.htm)

以下保留期和处理目标是项目拟定值，需要结合实际必要性与适用要求确定后再写入对外规则。

| **数据** | **首期处理方式** | **生命周期建议** |
| --- | --- | --- |
| 登录凭证 | 验证码只用于验证，日志脱敏，限频 | 按短时有效期处理，不保存明文凭证 |
| 学生档案 | 昵称、内置头像、年龄段、年级和时区 | 有效服务期间保留，支持更正和删除 |
| 任务记录 | 仅在授权档案范围内访问 | 可导出、按需删除，长期无使用时提示清理 |
| 复盘正文 | 默认学生个人可见，可主动分享 | 删除与撤回分享均有明确入口 |
| 会话与设备 | 加密传输，服务端撤销，限制缓存 | 登出或撤销后停止同步并清理 |
| 照片附件 | P1启用，私有对象、去除EXIF、限制类型大小 | 用户删除后进入清理任务，建议7天内清除在线副本 |
| 业务分析 | 使用匿名或去标识汇总，不采集正文 | 原始事件建议90天后删除或汇总 |
| 安全与操作日志 | 记录必要摘要，不记录令牌或儿童正文 | 依据适用要求单独确定保留期 |
| 备份 | 加密、限制访问、轮转 | 建议最长30天轮转，恢复时重放删除记录 |

### 13.2 数据访问与撤销

每个对象级接口验证当前学生权限；导出、上传签名、通知发送和后台任务也必须检查。撤销监护关系或设备授权后，旧会话立即失效，新的下载地址不再签发。

P1文件读取优先由鉴权代理控制，或采用不超过数分钟的短期签名链接。界面需明确短期链接在有效期内的访问边界；高敏感内容不使用长期公开地址。公共UI素材与学生附件使用独立访问策略。

导出与删除请求由有权主体发起并验证身份。建议在线数据删除目标为7天内完成，过程可查询；涉及必要保留的数据说明范围和依据。备份不能恢复已经删除的档案供业务继续使用。

### 13.3 发布与第三方依赖

发布前核验实际经营主体、部署地区、所选渠道的备案与审核要求，并检查登录、统计、短信、对象存储等第三方的数据处理范围。若未来增加公开发布或即时通讯，应重新评估身份、内容和未成年人保护要求。[[S7]](https://www.cac.gov.cn/2023-10/24/c_1699806932316206.htm)

P0学习记录不发送给外部AI。P1如增加AI计划建议，应先提供用户可确认的脱敏摘要，明确用途与供应商处理边界，允许不用AI完成全部基础任务。建议仍需人工确认后才能写入计划。

安全设计还包括管理员二次验证、接口限频、CSRF与XSS防护、依赖与密钥扫描、测试数据隔离、恢复演练，以及紧急撤销会话能力。它们作为验收条件，不以笼统的“已安全”代替检查结果。

## 14 验收标准与测试计划

### 14.1 核心场景验收

| **编号** | **场景** | **通过条件** |
| --- | --- | --- |
| T01 | 未满14岁档案开通 | 必要授权完成前不创建正式学习记录；版本可追溯 |
| T02 | 学制与年级 | 六三、五四及自定义正确映射，升年级保留历史 |
| T03 | 重复任务 | 指定星期和起止日期准确，多次生成无重复实例 |
| T04 | 修改计划 | 仅本次与未来范围正确，完成记录不被覆盖 |
| T05 | 连续点击完成 | 多次提交只产生一条有效记录和一份奖励 |
| T06 | 补记与撤销 | 日期窗口、来源标记、报告版本和奖励修正一致 |

| T15 | 手机操作 | 360至430px不溢出，主要操作可触达且文字可读 |

### 14.2 测试分层

业务单元测试集中在重复规则、时间边界、状态转换、幂等和统计口径。数据库集成测试验证唯一约束、事务回滚、并发完成、授权撤销和跨档案越权。端到端测试覆盖监护人开通到学生完成、周复盘和删除申请的关键路径。

界面做真实设备验证，至少覆盖常见Android浏览器、iPhone Safari和微信内置浏览器。日期筛选、软键盘、页面后台恢复、弱网和共用设备切换要人工确认。测试不承诺证明孩子实际专注，只验证记录和交互的正确性。

### 14.3 性能与运行目标

试点容量按约100个家庭预留。初始测试目标为100个活跃会话、读写混合访问时普通API的P95响应低于500毫秒；报告与导出采用异步处理。该目标需在记录清楚的测试资源与数据量下验证。

建议初期恢复点目标为24小时内、恢复时间目标为4小时内。上线前实际执行一次备份恢复并记录结果。性能和恢复目标均为验收目标，不是未经部署验证的服务保证。

## 15 试点与产品指标

### 15.1 试点安排

建议邀请24个家庭进行14天试用：小学一至二年级4个，小学三至六年级12个，初中4个，高中4个。先用5个家庭完成引导与任务记录的可用性检查，再扩大到全部试点。招募和联系由项目负责人安排，本方案不自动发送邀请。

第一次观察孩子能否选择模板、修改一项任务、开始学习并记录结果。第7天收集一次周复盘，第14天检查是否还愿意继续使用，并访谈孩子与家长各自认为有帮助或有压力的环节。

### 15.2 指标定义

| **指标** | **计算或观察方式** | **试点判断用途** |
| --- | --- | --- |
| 首次成功 | 完成开通且创建并记录第一项任务的档案／已开通档案 | 判断引导是否复杂 |
| 第二周使用 | 第8至14天至少2个学习日有有效完成的档案／第一周活跃档案 | 判断是否有持续价值 |
| 自主制定比例 | 学生自主创建或明确确认的任务／全部新增任务 | 判断孩子是否参与 |
| 调整情况 | 改期、拆分、跳过的次数和原因 | 发现模板负担与安排问题 |
| 周复盘使用 | 提交简短复盘的档案／当周活跃档案 | 判断总结是否有用 |
| 催促变化 | 试用前后家长自报并结合访谈 | 仅作方向判断，不能证明因果 |
| 体验压力 | 孩子反馈被催促、被比较、奖励分心的情况 | 发现需要删减的设计 |
| 技术可靠性 | 提交失败、重复记录、同步冲突和越权问题 | 判断能否扩大试用 |

可暂用首次成功率70%、第二周使用比例50%作为内部讨论线。这些是试点假设，不是行业基准；小样本只用于发现问题。连续几天登录、累计在线时长和分享次数不作为产品主要成功指标。

### 15.3 扩大范围的条件

只有当主要流程可用、没有未处理的严重权限问题、失败数据可恢复，且孩子与家长均能说明实际价值时，才进入更多家庭试用。若主要问题是任务太多或家长代操作过重，先调整模板与协作方式，再增加功能。

单名全职开发者承担主要工作的日历估算约9至12个工作周，再加2周试点；两名配合熟练的开发者可争取6至8周完成工程阶段，但认证、数据模型和联调存在顺序依赖，不能简单对半。上述日历估算尚未计入下一节的20%缓冲及外部等待时间。

### 16.2 后续阶段

P1根据试点结果选择微信小程序、照片记录、协作监护人、周频习惯和更完整的学期报告，不默认全部一起做。先解决首批家庭反馈最多且能明确验证的问题。

P2再评估原生应用、大学模式、AI辅助拆计划、题目与内容服务、家庭订阅。AI、题库或付费不能挤占核心记录可靠性的修复工作。

### 16.3 预算计算方式

人力预算按“42至58人日×实际综合人日成本”测算，再预留约20%的需求与兼容性缓冲。该缓冲是项目估算，不是供应商报价。若由本人和AI工具完成，需要单独计入本人投入、测试设备和外部审阅成本。

基础设施预算包含API运行、数据库、备份、域名、验证码、日志与监控。P0没有学习照片和AI调用，可减少按量费用。部署前按试点人数、地区与实际供应商重新询价，设置预算告警，不使用未经核验的云价格。

P1照片容量可以按“家庭数×每家学生数×每日图片数×单图大小×保留天数”估算。例如100个家庭、每家1名学生、每天2张、每张0.5MB、保存30天，原图约3GB；流量、缩略图与备份另算。

## 17 运营与商业化假设

首期免费试用，建立使用价值与服务反馈渠道。模板以原创的学习安排示例为主，明确适用学段、完成标准和可修改项。发布前检查可读性、任务负担、来源与版权，不将示例包装成未经验证的提分方案。

后续可以保留基础计划、完成记录、简单成长报告和数据权利功能免费；付费候选包括更多家庭协作、个性化报告和跨设备便利功能。是否收费及价格在试点后通过家长访谈和真实成本确定。

首期不接广告、奖励抽奖或付费补签。新增商业化也不得降低基础隐私、导出和删除能力。支付、订阅续费与退款需要独立产品规则和技术审查后再开发。

| **风险** | **早期信号** | **应对** |
| --- | --- | --- |
| 只签到不学习 | 记录频繁但说不出完成内容 | 强化明确标准和简短成果记录 |
| 家长变成唯一操作者 | 自主制定比例低，孩子只被通知 | 调整共同制定流程，减少强制任务 |
| 覆盖学段过多 | 模板与页面维护失控 | 保留分类，集中验证主要人群 |
| 数据可信度混淆 | 自报记录被当成真实能力评价 | 清楚标记来源，不作能力排名 |
| 功能持续膨胀 | AI、题库、商城先于核心流程 | 通过P0清单和验收门槛控制范围 |
| 上线成本失控 | 图片、通知或调用量高于预期 | 分阶段启用，配额和费用告警 |

仓库应维护docs/PRODUCT_SCOPE.md、docs/BUSINESS_RULES.md、docs/PAGES.md、docs/DATA_MODEL.md、docs/API.md、docs/ACCEPTANCE.md与docs/CURRENT_STATUS.md。文档记录决策和完成证据，不堆积相互矛盾的平行方案。

每次实施报告包含任务编号、分支与前后HEAD、改动原因、修改文件、用户可见变化、数据库迁移与回滚情况、实际执行的测试及结果、保留的已有改动、未解决问题。未执行的测试标为未执行，不能写成通过。

本方案的默认方向可以直接进入交互设计和任务拆分。正式开发前需最终确定的业务项为品牌名称、经营与隐私责任主体、首批家庭实际入口，以及可投入的开发人力；它们不影响先完善页面与纯业务规则。
